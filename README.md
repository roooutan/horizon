# 전문용어 정책 구축 및 번역 모델 학습·평가

## 1. 전문용어 Glossary 구축

컴퓨터공학 학술 논문에서 전문용어의 원어 유지 및 한국어 번역 기준을 일관되게 적용하기 위해 전문용어 Glossary를 구축하였다.

**① 선행 작업: 데이터셋 정제 및 검증**

- KCI 기반 영어·한국어 논문 초록 데이터 약 10,059건의 품질을 점검하였다.
- JSON 형식 오류, 결측값, 중복 문장, 번역문 충돌, 원문·번역문 길이 불일치 등을 검사하였다.
- 중복 및 정렬 오류가 있는 데이터를 정제하고, 전문용어가 포함된 문장을 별도로 검토하였다.
- 정제된 데이터에서 학습 후보 4,972건을 확보하고, 용어 정책을 적용할 수 있는 문장과 문맥상 판단이 필요한 문장을 구분하였다.

**② Glossary 구성 기준**

전문용어별로 다음과 같은 정책을 적용하였다.

- **KEEP:** 번역하지 않고 영어 원어를 유지해야 하는 용어
- **TRANSLATE:** 정해진 한국어 전문용어로 번역하는 것이 적절한 용어
- **Context-sensitive:** 문맥에 따라 번역 여부나 표현을 판단해야 하는 용어
- **Auto-enforce:** 자동으로 번역 규칙을 강제하고 평가할 수 있는지 나타내는 속성

기존에 구축한 Glossary와 팀원들이 제공한 용어 정책을 통합하였으며, 중복되는 항목에서 정책이 충돌할 경우 팀의 합의된 정책을 우선하였다.

초기 Glossary 100개에 팀 데이터의 고유 용어 77개를 추가하여 177개로 병합한 뒤, 후속 검수를 거쳐 **최종 172개 용어(KEEP 45개, TRANSLATE 127개)**로 구성하였다.

최종 Glossary에는 용어별 번역 방식, 허용 번역어, 변형 표현, 약어, 문맥 의존 여부 등을 저장하였다.

**③ 용어 정책 설계 배경 및 문맥 기반 처리**

일부 전문용어는 한국어로 직역하면 원래의 기술적 의미가 흐려지거나 표현이 길고 낯설어져 오히려 이해하기 어려울 수 있다. 따라서 **원어 표기가 중요한 용어는 KEEP**, 한국어 표현이 널리 정착된 용어는 **TRANSLATE**로 분류하고, 그 외 일반적인 문장 서술은 자연스러운 한국어로 번역하는 것을 기본 방향으로 설정하였다.

또한 `tree`, `parent`, `child`처럼 컴퓨터공학에서는 특정 자료구조·노드 관계를 가리키지만 일상 문맥에서는 일반적인 사물을 뜻할 수도 있는 단어는 **단순 문자열 치환보다 문맥에 맞는 해석이 중요하다**고 보았다. 이러한 다의적 표현을 고려하여 문맥 의존 여부를 별도로 표시하고, 무조건적인 자동 강제를 제한하는 기준을 두었다. *(예시는 설계 취지 설명을 위한 것이며, 해당 단어 모두가 최종 Glossary에 등록되었다는 의미는 아니다.)*

## 3. 전문용어 번역 모델 추가 학습

**① 모델 구성**

- Base Model: `tencent/Hy-MT2-7B`
- 초기 모델: 팀원이 컴퓨터공학 논문 데이터로 Fine-tuning한 CS LoRA
- 학습 방식: LoRA 추가 학습, 4-bit NF4 양자화 활용
- 학습 환경: RunPod GPU
- 학습량: 800 steps

기존 CS LoRA를 기반으로 전문용어 정책이 반영된 데이터로 추가 학습하여 **Terminology LoRA**를 구축하였다.

**② 학습 데이터**

KCI 논문 기반 영어·한국어 병렬 데이터와 최종 Glossary를 활용하였다.

학습 데이터는 총 1,930건이며, 다음과 같이 구성하였다.

| 데이터 유형 | 건수 |
|---|---:|
| 전문용어 규칙 적용 데이터 | 243 |
| 문맥 의존 용어 포함 데이터 | 1,187 |
| 일반 번역 데이터 | 500 |
| **합계** | **1,930** |

학습·검증·테스트 데이터는 각각 1,930건, 620건, 624건으로 분리하고, 문서 및 문장 중복 여부를 검사하였다.

**③ 모델의 목적**

일반적인 영어→한국어 번역 능력을 유지하면서, 학술 논문에 등장하는 전문용어를 사전에 정의된 정책에 따라 일관되게 처리하도록 하는 것이 목적이다.

학습된 모델은 LoRA Adapter 형태로 저장하고 GitHub Release를 통해 팀원에게 전달하였다.

## 4. 기존 Terminology LoRA 성능평가

기존 CS LoRA와 추가 학습한 Terminology LoRA를 동일한 평가 데이터에서 비교하였다.

**① 전체 번역 품질**

KCI 테스트 데이터 624개를 사용하여 BLEU와 chrF를 측정하였다.

| 지표 | 기존 CS LoRA | Terminology LoRA |
|---|---:|---:|
| BLEU | 26.71 | 26.62 |
| chrF | 35.00 | 35.06 |

추가 학습 이후 일반 번역 품질에서 뚜렷한 개선은 확인되지 않았다.

**② 전문용어 정책 준수율**

Glossary에서 자동 평가가 가능한 용어 95개를 선정하고, 일반 번역 지시문과 Glossary 규칙을 명시한 지시문을 각각 적용하였다.

| 평가 조건 | 기존 CS LoRA | Terminology LoRA |
|---|---:|---:|
| 일반 지시문 | 68.42% | 65.26% |
| Glossary 명시 | 92.63% | 93.68% |

추가 학습 자체의 개선 효과는 제한적이었으나, Glossary 규칙을 명시적으로 제공하면 두 모델 모두 높은 정책 준수율을 보였다.

**③ Markdown 구조 보존 예비 평가**

기존 두 모델에 대해 합성 Markdown 문서 36개를 이용한 구조 보존 예비 평가를 진행하였다. 제목, 목록, 표, 코드, 수식 등의 구조 요소 75건을 검사한 결과 두 모델 모두 74건(98.67%)을 보존하였다.

이는 합성 데이터에 대한 예비 평가이며, 현재 팀의 최종 모델 및 실제 PDF 변환 시스템의 성능을 나타내는 수치는 아니다.

## 5. 최종 번역 시스템의 외부 모델 비교 평가 (완료)

팀 최종 시스템(Stage4 + Glossary 프롬프트 + Reranker)의 성능을 확인하기 위해 공개 번역 모델 3종을 비교 대상으로 설정하였다. 직접 수행한 외부 모델 평가에는 **동일한 KCI 기반 테스트 624개**, 동일한 Glossary 및 팀 공통 평가 코드(`python -m evaluation run`)를 사용하였다. 테스트 데이터와 Glossary 파일의 SHA-256 해시가 세 실험에서 일치하고, 각 모델의 실제 채점 데이터는 모두 624개(`n_scored=624`)임을 확인하였다.

| 모델/시스템 | BLEU (ko-mecab) ↑ | chrF ↑ | 팀 전문용어 정책 준수율 ↑ | 숫자 보존율 ↑ |
|---|---:|---:|---:|---:|
| M2M100-418M | 8.9686 | 18.2027 | 54.55% | 51.14% |
| NLLB-200 distilled 600M | 13.9347 | 23.6003 | 75.76% | 68.53% |
| Hy-MT2-7B 원본 | 22.7267 | 31.3833 | 93.94% | 96.27% |
| 팀 최종 시스템 (E_all)* | 28.2284 | 36.6947 | 98.48% | 96.69% |

*팀 최종 시스템 점수는 팀원 저장소의 `results/final/compare.md`에 기록된 값이다. 외부 모델의 직접 평가 결과와 구분되며, 최종 시스템의 원본 예측 JSONL은 이번 실험에서 별도로 재채점하지 못했다.*

평가 지표는 SacreBLEU의 BLEU(`ko-mecab`), chrF, Glossary KEEP/TRANSLATE 정책 준수율, 숫자 및 일부 구조 요소 보존율, 반복·비정상 출력 등이다. 전문용어 정책 준수율은 **자동 판정 가능한 66개 용어 사례(KEEP 36, TRANSLATE 30)**에 대한 점수로, 전체 문장 624개의 정답률과는 다르다. Hy-MT2 원본 추론에서 출력 상한에 도달한 4건은 별도 재번역 후 병합하여 624개를 다시 채점하였다.

**비교의 한계:** 외부 모델은 일반 번역 조건으로 실행한 반면 팀 최종 시스템은 Stage4 추가 학습, 용어 규칙, 문맥 및 Reranker를 결합한 시스템이다. 또한 모델별 디코딩 방식과 출력 길이 설정이 완전히 같지 않다. 따라서 BLEU/chrF 점수 차이를 특정 학습 단계 또는 Reranker 하나의 효과로 단정할 수 없고, **시스템 수준 비교 결과**로 해석해야 한다. 팀 최종 시스템 자체의 Reranker 기여도는 팀원이 별도로 수행한 단계별 ablation 평가에서 확인할 수 있다.

## 6. 최종 Markdown 구조 보존 및 PDF 통합 평가 (완료: 제한적 샘플)

최종 Stage4 + Reranker에 Markdown 입력을 전달하여 한국어 Markdown을 생성하고, 원문과 번역문의 제목·목록·수식·코드·이미지 참조·표 등을 비교하였다. 표는 **내용을 번역하지 않고 영어 원문과 구조를 그대로 보존**하는 팀 정책을 적용하였다. 이후 팀원이 구현한 Pandoc + XeLaTeX 기반 Markdown→PDF 코드로 출력 PDF를 생성·렌더링하였다.

| 평가 데이터 | 번역 단위 | 구조 진단 결과 | PDF 생성 및 시각 검증 |
|---|---:|---|---|
| 실제 논문 PDF→Markdown 자동 변환 샘플 (원본 PDF 2페이지) | 53개 | **6/6 유형 검사 통과** | 한국어 PDF 4페이지 생성, 이미지 3개·표·수식 표시 확인 |
| 합성 Markdown 구조 테스트 (추가 유형 포함) | 23개 | **15/15 유형 검사 통과** | 한국어 PDF 2페이지 생성, 목록·코드·수식·표·그림·각주 표시 확인 |

실제 논문 샘플은 제목 2개, 이미지 참조 3개, 인라인 수식 5개, Markdown 표 관련 줄 9개 및 굵게 표시 마커 10개를 검사하였다. 합성 테스트에는 제목·중첩 목록·인용문·이미지·링크·코드블록·독립/인라인 수식·인라인 코드·표·인용·각주·URL·굵게 표시 등이 포함되었으며, 총 15개 **유형별 휴리스틱 검사**를 통과하였다. 양쪽 테스트에서 이미지 경로 누락은 없었다.

실제 한국어 PDF는 4페이지, 합성 구조 테스트 PDF는 2페이지로 출력되었다. 합성 테스트에서는 Markdown 원문에 포함된 한국어 **403자가 PDF 텍스트에서도 모두 확인**되었다. 각주가 조판 과정에서 페이지 하단으로 이동하므로 PDF 추출 텍스트의 순서는 Markdown과 다를 수 있으나, 각주를 제외한 한국어 문자 순서는 일치하였다.

**해석의 한계:** 6/6과 15/15는 *해당 샘플에서 적용 가능한 검사 항목 유형*의 통과율이며, Markdown 문법 전체나 임의의 학술 PDF에 대한 100% 보존율을 의미하지 않는다. 실제 논문의 PDF→Markdown 자동 인식 단계에는 수식·단어 분리 오류 가능성이 남아 있다. 원본 논문의 2단 레이아웃과 페이지 수는 재현하지 않고 새로운 단일 단 PDF로 조판했다. 한국어 PDF의 일부 페이지에 여백이 크게 남았고, 합성 번역 결과에서 일부 영어 안내 문장이 번역되지 않은 사례도 확인되어 별도의 품질 개선이 필요하다. 표 내부 텍스트 및 이미지화된 표는 팀 정책에 따라 영어 그대로 유지하였다.

## 7. 기존 추가 학습의 한계 및 후속 개선 방향

Terminology LoRA의 추가 학습 결과, CS LoRA 대비 일반 번역 품질의 뚜렷한 향상은 확인되지 않았다(BLEU 26.7069→26.6170, chrF 35.0033→35.0575). 반면 전문용어 규칙을 명시적으로 제공한 집중 평가에서는 높은 정책 준수율을 확인하였다. 이는 전문용어 처리를 위해 학습 데이터의 개선뿐 아니라 **명시적인 Glossary 정책 제공과 후처리·후보 선택 등 시스템 설계**를 함께 고려해야 한다는 근거로 해석할 수 있다. 다만 팀 최종 시스템의 성능 향상을 Terminology LoRA의 기여로 해석하지 않았으며, 최종 시스템은 별도 Stage4 LoRA와 Reranker를 사용한다.

향후에는 실제 논문 여러 편을 대상으로 제목 계층·복잡한 표·혼합 수식·그림·각주·다단 구성에 대한 자동 검사와 전문가 수동 검수를 병행하고, PDF 페이지 구성 및 번역 표현의 자연스러움을 개선할 예정이다.
